# KTake · Mac 录唱工作台

原生 SwiftUI / AVFoundation 应用，面向 macOS 14 及以上版本。无外部依赖，无需安装完整 Xcode，有 Apple Command Line Tools 即可构建。

## 启动

```sh
./scripts/build-app.sh
open "dist/KTake.app"
```

构建产物为 `dist/KTake.app`，本地临时签名，未经过 Apple 公证。源代码位于 `Sources/KTVPro`。KTake 沿用旧版 KTV Pro 的本地数据目录，可以直接读取已有曲库、录音和练唱设置。

构建脚本会检测旧版 Command Line Tools 遗留的重复 `SwiftBridging` 模块定义；如果存在，仅通过项目内 VFS overlay 绕过旧定义，不修改系统开发工具。

应用图标由 `Tools/RenderAppIcon.swift` 绘制；修改后运行 `zsh scripts/render-icon.sh` 可重新生成 macOS 图标和 PNG 预览。

## GarageBand 分轨导出（0.9.2）

在「我的录音」打开一条录音的 `…` 菜单，选择「导出到 GarageBand…」，勾选使用同一伴奏和调性的录音。导出结果是独立的 44.1 kHz / 24-bit WAV，每条人声为单声道，伴奏为立体声并保留录唱时的升降调。录音按采集时间对齐，旧录音用记录的播放起点估算。分轨保留干声，补录也可以单独导出。

导出后 KTake 会在 Finder 中选中这些文件，并打开已安装的 GarageBand。在 GarageBand 新建空白项目，把每个 WAV 放在轨道区最左侧的同一起点，再按 ⌘S 保存 `.band` 工程。

## 分段练唱与补录（0.9）

- 主界面的歌词区会跟随播放并高亮当前句。用滚轮或触控板浏览完整歌词，点击一句即可跳转；手动浏览后点「回到当前句」即可恢复跟随。有 MV 时，歌词列表在画面下方。「歌词定位」也可以打开独立的列表。
- 用「设 A」「设 B」圈出一段，再用「循环」反复练唱；跳到范围外会关闭循环。
- 「录前准备」可以选直接录、倒数 3 秒、倒数 5 秒或先听最多 3 秒伴奏。从歌曲开头录制或没有伴奏时，先听伴奏会改用倒数。
- 「我的录音」按曲目分组。用行菜单标记一条首选录音，或添加备注；搜索也会匹配备注。
- 启用麦克风后，打开原录音的「回听与混音」，设定 A/B 点并选择「准备补录…」，回到主界面点击「开始补录」，到 B 点自动结束。重开原录音即可在 A 原版和 B 补录之间切换、只听 A–B，或「采用」其中一条补录。只替换实际录到的部分；混音导出使用当前版本，原始 WAV 保留。

## 录音回听与练唱设置（0.8）

- 「我的录音」点击曲名或在行菜单选择「回听与混音」，可切换只听人声或带伴奏、调节两路音量、微调人声对齐。录音从歌曲中段开始时，回听和导出都使用当时的伴奏位置及升降调。导出立体声 48 kHz / 24-bit WAV，保留原始单声道 WAV；混音不包含实时监听效果。
- 录音列表的播放按钮会按开录时的明亮度、压缩、混响和监听音量回听人声；当时没开实时监听则播放干声。只保存过混响的旧录音仍按原来的混响回听，未记录混响的旧录音沿用右侧当前混响。「回听与混音」可以分别调节明亮度、压缩、混响与人声音量，关闭人声效果对比干声，或恢复开录时的效果设置。原始录音、WAV 和 GarageBand 分轨导出不写入人声效果。
- 新录音使用麦克风第一帧的主机时钟与播放器起点对齐；旧录音按保存的开始位置估算。人声偏移正值让人声变晚，负值让人声提前，可补偿实际设备的偏差。原伴奏不在时仍可只听人声。
- 每首曲目分别保存调性、歌词及其偏移、播放位置。重开时恢复最后选中的曲库歌曲，保持暂停；唱完的歌曲回到开头。
- 启用麦克风后，录音按钮旁可「试音」。最多录制 5 秒，可以提前结束，右栏显示输入是否太弱、是否接近爆音，并可回听。试音不会写入正式录音列表。

## 曲库与录音管理（0.7）

左栏在「本地曲库」和「我的录音」之间切换。曲库支持按歌名、歌手搜索，按最近加入、歌名或歌手排序。录音可按歌名搜索；每行的播放按钮可回听，`…` 菜单可导出 WAV 或删除。

曲目行的 `…` 菜单可在 Finder 中查看伴奏，或移出曲库。下载曲目只会将应用保存的副本移到废纸篓；附带曲目会隐藏，左栏底部菜单可以恢复。若要还原已移到废纸篓的曲目或录音，把曲目文件夹或录音文件放回原目录，再刷新相应列表。录音需要放回 WAV 和同名 JSON 两个文件。

## 本地曲库与升降调（0.3）

- 左栏「本地曲库」可以选择曲目；启动时恢复最后选中的曲目（没有记录时准备第一首），不自动播放。
- 已整理用户提供的 Aimer《Ref:rain》伴奏：`Library/Songs/Aimer/Ref-rain/accompaniment.mp3`，约 02:01、320 kbps、44.1 kHz、双声道。只移动文件，没有重新编码；原文件 SHA-256 记录在歌曲目录的 README 和曲库清单中。目前没有对应 MV 或 LRC。
- 曲库清单是 `Library/catalog.json`，支持曲名、歌手、伴奏路径、可选 MV / LRC 路径。构建时复制到应用资源目录，因此移动 `.app` 后仍能选用这些曲目。
- 右侧「伴奏升降调」支持 −6 到 +6 个半音、恢复原调，速度保持不变。只处理独立伴奏，实时麦克风监听和原始人声不做变调。
- 首次切换先在后台离线处理伴奏，显示进度，完成后恢复原播放位置和播放 / 暂停状态。对应调性的结果缓存后可直接复用；原调始终使用原文件。录音期间锁定升降调，请在录音前选好调性。
- 升降调缓存位于 `~/Library/Caches/KTV Pro/Pitch/v1/`，以原文件内容校验值和半音数区分；临时处理失败不会覆盖原伴奏。缓存为浮点 PCM CAF，每个调性会占用额外磁盘空间。
- 录音 JSON 会记录当时的半音数和曲目编号，旧版本录音仍然兼容。

## 5sing 伴奏搜索与下载（0.4）

点击本地曲库左栏底部的「5sing 找伴奏」，在独立窗口搜索歌曲。网页中的「伴奏」筛选、登录、扫码和验证码由 5sing 自己提供，登录会话由 WebKit 在本机保存。应用不会读取账号密码，也不会使用试听流代替下载。

下载前会从搜索结果或歌曲详情自动识别曲名和「原唱」，不使用上传者昵称作为歌手；窗口底部支持修改。页面信息缺失时尝试音频内嵌标题、歌手标签，最后使用原文件名和「5sing」。点击网站正常下载入口，文件下载完成后校验音频、复制到曲库并刷新可选曲目。录音或加载歌曲期间完成下载时，暂不切换当前歌曲，结束后点击「刷新曲库」即可选择。

新下载的歌曲保存在 `~/Library/Application Support/KTV Pro/SongLibrary/`，与应用内置歌曲合并显示，重启和重新构建应用都保留。清单记录标题、歌手、时长和来源页面，原始下载音频不重新编码。网页或错误提示文件不会作为音频入库。

网站可能要求登录、安全验证，或对个别歌曲限制下载，需要在网页中完成。若内嵌网页无法完成，使用「外部浏览器」下载，再点「导入已下载文件」。外部浏览器的登录状态与应用内 WebKit 会话独立。

已验证应用内搜索页和扫码登录界面；下载接收、实际 MP3 校验、曲库持久化与合并通过本机 HTTP 附件测试。真实账号登录后的最终下载仍需用户完成站点验证后确认。

## 手动搜索歌词（0.6）

在「导入 LRC 歌词」旁点击「从 LRCLIB 搜索」，或从顶部点「搜歌词」。窗口会用当前歌名和歌手开始搜索；可以修改歌名，也可以把歌手留空。

结果只显示带时间轴的歌词，列出歌手、专辑和时长。手选版本有时长差也能导入，应用会标出差值。点击对应结果的「导入」即可加载；曲库歌曲会记住手选版本，下次选中时自动载入。

## 自动命名与同步歌词（0.5）

- 下载入库的音频统一保存为 `歌手 - 曲名 (伴奏).mp3`（保留原格式）；非法路径字符会清理，冒号变为全角 `：`，中文、日文保留。每首曲目使用独立目录，重名也不会覆盖其他歌曲。导入已有本地文件时只命名曲库副本，不改动原文件。
- 优先使用当前歌曲页面提供的有效 LRC；否则查询 LRCLIB 的公开只读搜索接口，只发送曲名和歌手，不上传音频或账户信息。结果同时核对曲名、歌手、音频时长（误差最多 3 秒），并验证时间戳与音频长度。只有可信匹配才自动绑定，未知歌手存在歧义时不自动选择。
- 匹配的 LRC 使用音频同名文件保存，曲库记录其相对路径与来源，选择曲目时自动载入。网络失败或无匹配不会丢失已下载伴奏，窗口和无歌词画面会提示，仍可手动导入 LRC。
- 短版、TV 版、剪辑版可能找不到对应时序；不会将完整版歌词强行附到短版上。已核实 LRCLIB 的 Aimer《Ref:rain》搜索结果，当前 2:01 伴奏没有符合时长的同步歌词记录；未伪造时间轴。
- 请求按序限速、缓存搜索结果，服务返回 429 / 503 时按 `Retry-After` 冷却。文档：[LRCLIB API](https://lrclib.net/docs)。

`zsh scripts/test-lyrics.sh` 验证匹配规则与安全文件名。下载集成测试使用本机附件与歌词 HTTP 测试服务，覆盖下载、自动命名、歌词查询、同名 LRC 保存与曲库关联；测试不启用麦克风。

## 使用

1. 点击「导入伴奏」（⌘O），选择本地 MP3、M4A、WAV、AIFF 等音频。伴奏可以单独使用。
2. 可选：点击「MV」（⇧⌘O）导入 MP4 / MOV。独立伴奏存在时只保留 MV 画面，不播放 MV 原音；只有 MV 时，仍可播放其自带音轨。三个素材槽各自支持移除。
3. 点击「歌词」（⌘L）导入带时间戳的 LRC。没有 MV 时，主区域显示上一句、当前高亮句、下一句和底部播放进度；有 MV 时在画面上叠加歌词。支持 UTF-8、带 BOM 的 UTF-16、GB18030 编码，支持重复时间标签、毫秒和 `[offset:...]`。目前按句高亮，不做逐字动画。
4. 主区域右上角的「歌词延后」可按 0.25 秒调整：正值让歌词晚出现，负值让歌词早出现。拖动进度后歌词随位置更新。
5. 右侧选择输入、输出和麦克风通道，点击「启用麦克风」。首次使用需要同意系统麦克风授权。
6. 戴上有线耳机后打开「实时效果监听」。连接福克斯特后刷新设备，输入和输出都选择声卡，耳机接声卡，关闭声卡 Direct Monitor。监听默认关闭。没有音频输入的 Mac mini 需连接声卡或麦克风。
7. 调节自然人声 / 温暖抒情 / 清晰干声预设，或手动调整人声音量、明亮度、压缩和混响。输入过载时调低声卡上的物理增益。
8. 点击「开始录音」（⌘R），同时播放歌曲并录制人声。没有歌曲时也可以单独录音。录制中锁定切换设备、导入、定位和暂停操作；「结束录音」会暂停歌曲并完成 WAV 写入。伴奏正常播放到末尾也会结束录音。
9. 在「我的录音」中直接回听人声、导出原始 WAV，或打开录音文件夹。回听期间自动关闭麦克风监听，结束后恢复原设置。声卡断开后也能通过其他输出设备回听。

伴奏与 MV 使用同一个 AVComposition / AVPlayer 时间轴，统一播放、暂停和定位，从文件开头对齐。歌曲时长以独立伴奏为准：MV 较长时截到伴奏结尾，MV 较短时在视频结束后显示歌词并继续伴奏。不同剪辑版本的 MV 和伴奏可能需要预先对齐，目前没有 MV 偏移调节或自动匹配。

切换设备后需要重新启用麦克风。麦克风权限被拒绝时，应用会提供系统设置入口。

## 保存与音频路径

- 人声：单声道、设备当前采样率、24-bit PCM WAV。
- 默认目录：`~/Library/Application Support/KTV Pro/Takes/`，每段 WAV 有对应的 JSON 录音信息。
- 关闭窗口或退出时，会等待正在录制的 WAV 写入完成。
- 设备断开、格式改变或磁盘背压时，停止录音并保留已写入的音频，同时标记异常。
- 系统强制终止 / 断电时只能尽力恢复文件，不能保证最后一段 WAV 完整；初始 JSON 会标记为未完成。

```text
麦克风物理通道 → 单声道捕获 ┬→ 预分配缓冲池 → 独立写盘队列 → 原始人声 WAV
                          └→ 高通 / EQ → 压缩 → 板式混响 → 监听音量 / 静音 → 耳机
独立伴奏（优先）或 MV 自带音轨 ───────────────────────────→ 同一输出设备
```

原始录音不包含伴奏、MV 音轨和监听效果；人声效果在回听时才加入。JSON 额外记录伴奏和歌词文件路径及开录时的监听设置，兼容旧版录音。目前不包含音视频合成、自动人声分离或音准评分。

## 验证

```sh
./scripts/test-audio.sh
./scripts/test-mix.sh
./scripts/test-playback.sh
./scripts/test-pitch.sh
```

音频冒烟测试不打开麦克风或扬声器：验证实际 24-bit WAV 帧数和样本、停止后的缓冲拒绝、写盘背压、输入电平与过载，以及 Apple EQ / 压缩 / 混响链的离线渲染。

播放测试使用生成的无声视频和伴奏，验证 LRC 解析、原音轨替换、共同时间轴、长短素材边界、歌词随进度定位、移除素材和导入失败恢复；不启用麦克风。

升降调测试使用已知频率的双声道信号，检查升降后的实际频率、输出帧数、声道数、起始位置、缓存复用及原文件校验值；也对用户提供的 MP3 做了降两个半音的离线验证。播放集成测试同时检查曲库选择与切调后的进度、歌词和暂停状态。

仍需实机验证的部分：

- 麦克风权限、实际输入通道、声卡拔插和长时间录唱。
- 真实监听往返延迟、爆音与掉帧。页脚显示设备缓冲帧数，不将它换算成未经实测的总延迟。当前沿用设备缓冲，不更改全局硬件采样率或缓冲。
- 麦克风录音由独立音频引擎采集，新录音使用主机时钟对齐起点。设备的真实往返延迟和长时间漂移仍需实机测试；可在回听里手动微调起点。
- 没有连接福克斯特时，无法验证其驱动、通道映射和监听表现。

原型的目标是先检验「MV 播放 + 人声录制 + 实时效果监听」这条实际链路，后续用具体声卡完成延迟和稳定性调校。
